# Glossary

Quick reference for terms used in the project docs and codebase.

---

## Auth + identity

**Clerk** — third-party authentication service handling sign-up, login, password reset, OAuth. We don't store passwords; Clerk does.

**JWT (JSON Web Token)** — signed token Clerk returns after login. Frontend attaches it to API requests as `Authorization: Bearer <token>`. API verifies the signature using Clerk's public keys.

**JWKS (JSON Web Key Set)** — the file at `<clerk-issuer>/.well-known/jwks.json` listing Clerk's public keys. Our `ClerkJwtVerifier` fetches it once per hour (cached) to verify incoming JWTs.

**AuthAccount** — table linking a Clerk user (`provider_user_id`) to our internal `Person` record. Lets us swap auth providers later without losing person data.

**Bootstrap super-admin** — the first signup whose email matches `BOOTSTRAP_SUPER_ADMIN_EMAIL` automatically gets `super_admin + admin + member` roles. Used for day-one and disaster recovery.

---

## Data + persistence

**EF Core (Entity Framework Core)** — Microsoft's ORM for .NET. Maps C# classes to Postgres tables.

**Fluent API** — the pattern of configuring entity-to-table mapping in dedicated `Configuration.cs` files using method chains (vs. `[Attribute]` annotations on the entity class itself).

**Migration** — a versioned change to the database schema, generated by EF and applied via `dotnet ef database update`. Migrations live in `apps/api/Data/Migrations/`.

**`HasQueryFilter`** — EF feature that adds a `WHERE` clause to every query for an entity. We use it to implement soft-delete: `b.HasQueryFilter(p => p.DeletedAt == null)` means deleted rows never appear in normal queries.

**Soft delete** — setting `DeletedAt` instead of removing the row. Preserves audit trail. Hard-delete happens 30+ days later via the retention cleanup job.

---

## API + HTTP

**RFC 7807 (Problem Details for HTTP APIs)** — IETF spec for a standardized JSON error shape. Every error response has the same fields: `type`, `title`, `status`, `detail`, `traceId`. The frontend has one error handler that understands all errors.

**Presigned URL** — a temporary URL signed with our DO Spaces credentials that grants permission to upload (PUT) a specific file to a specific key. Valid for 15 minutes. Lets the browser upload directly to Spaces without the API holding the file bytes.

**Bearer token** — auth scheme where the token goes in the Authorization header: `Authorization: Bearer <jwt>`.

**Rate limit** — cap on requests per time window. We use ASP.NET's built-in `AddRateLimiter` with named policies: `default`, `auth`, `comms`, `checkin`. Returns 429 with `Retry-After` header.

## SMS + email regulations

**A2P 10DLC** — Application-to-Person messaging on 10-Digit Long Codes. The carrier program that lets businesses send SMS from normal-looking numbers (vs. short codes). Requires brand + campaign registration through TCR.

**TCR (The Campaign Registry)** — third-party registry US carriers use to verify business SMS senders. Telnyx submits our brand + campaign here. Approval takes 1-3 days per stage.

**TCPA (Telephone Consumer Protection Act)** — US law requiring explicit consent before sending marketing SMS. Our signup form has an explicit opt-in checkbox; opt-in events go to the audit log.

**STOP keyword** — required by US carriers. When a user texts STOP to our number, Telnyx auto-replies "you've unsubscribed" and sends us a webhook. Our handler flips `person.sms_opt_in = false` and audit-logs.

**FERPA (Family Educational Rights and Privacy Act)** — US law protecting student education records. Since we handle GSU student data, we need faculty advisor sign-off on data handling.

**SES sandbox** — AWS SES default mode. 200 emails/day cap, only verified addresses. Removed by requesting production access.

**SPF / DKIM / DMARC** — email authentication DNS records. We add them to Cloudflare so receiving servers know our SES emails are legit and not spoofed.

## DevOps

**Docker Compose** — multi-container local dev. Our `docker-compose.yml` runs Postgres + API + (future) web with one command.

**Quartz.NET** — background job scheduler for .NET. We use it for the monthly retention cleanup job.

**GitHub Actions** — CI/CD platform. Runs `ci.yml` on every PR (build + test + lint).

**DigitalOcean App Platform** — DO's heroku-like hosting. Reads `.do/app.yaml` from the repo, auto-deploys on push to main.

**DO Spaces** — DO's S3-compatible blob storage. Same API as AWS S3, different endpoint. Our `IFileService` uses the AWSSDK.S3 NuGet package pointed at DO.

**Vite** — modern frontend build tool. Replaces Webpack/CRA for the React app.

**HMR (Hot Module Replacement)** — Vite + `dotnet watch` automatically reload code changes without restarting the server.

## Architecture patterns

**Endpoint / handler / service** — our 3-layer convention:
1. **Endpoint** (`Endpoints/*.cs`) — registers the route, applies filters
2. **Handler** — short Func passed to `MapGet`/`MapPost` etc.
3. **Service** (`Services/*.cs`) — does the actual business logic

Endpoints stay thin; services contain logic.

**DTO (Data Transfer Object)** — the shape of data going over the wire. Lives in `Contracts/`. Separate from `Models/` because we don't always want to expose every DB field externally.

**Middleware** — runs on every request in pipeline order. Our chain: Exception → CORS → RateLimit → ClerkAuth → AuditLog → Endpoint.

**Endpoint filter** — runs only on the endpoints it's attached to (`.RequireAdmin()`). Used for per-endpoint concerns like role checks.

**Repository pattern** — we DON'T use it. Services interact with `AppDbContext` directly. Simpler in small-to-medium projects.

## Project conventions

**Scaffolded** — has entities, real-shape endpoints, types, routes, page shells, TODOs. The lead delivers scaffolds.

**Done** — scaffolded + polished UI + validation + empty/loading/error states + mobile + accessibility + edge cases + tested in staging. The vertical owner delivers "done."

**Snake_case in DB, PascalCase in C#, camelCase in JSON/TS** — three different conventions for three layers. Fluent API does the translation via `HasColumnName("snake_case")`.

**Soft-deletable** — entity has nullable `DeletedAt` column + `HasQueryFilter`. Use for anything users might want restored.

**Audit-logged** — middleware logs generic mutations; services write to `audit_log` for specific actions (merges, bootstraps, retention).
